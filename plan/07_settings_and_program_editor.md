# Этап 07: Экран настроек и управление JSON-программой (Settings & Program Editor)

## 1. Цель этапа
Реализовать экран настроек приложения с возможностью визуального и прямого JSON-редактирования программы тренировок, настройки порогов таймера готовности, экспорта/импорта данных и сброса к заводским параметрам. Гарантировать, что редактирование программы не приводит к повреждению или мутации уже сохраненных дней в истории.

---

## 2. Детальный состав работ

### 2.1. Редактор программы тренировок (Visual & JSON Editor)
- **Визуальный режим:**
  - Просмотр дней (День А, День Б, возможность добавить День В).
  - Список упражнений: добавление нового движения, удаление, редактирование названий, целевых сетов, дефолтных повторений и рабочего веса.
- **Прямой JSON-редактор:**
  - Встроенное поле с подсветкой синтаксиса для редактирования сырого JSON программы.
  - Кнопка «Сбросить к дефолтной программе».
  - Валидация схемы JSON перед сохранением: проверка обязательных полей (`id`, `name`, `targetSets`, `defaultReps`).
- **Защита истории от повреждений:**
  - При сохранении новой программы пользователю показывается уведомление: *«Изменения вступят в силу для сегодняшних и будущих тренировок. Вся история тренировок сохранена без изменений»*.

### 2.2. Экспорт и импорт программы (`program.json`)
- Кнопка скачивания файла `gtg-program.json` (только программа).
- Кнопка загрузки файла `gtg-program.json` с валидацией структуры.

### 2.3. Настройки таймера и взаимодействия
- Настройка порогового времени отдыха между подходами (слайдер или числовое поле, по умолчанию 60 минут, диапазон 30–120 мин).
- Переключатель тактильного отклика (Haptic Feedback вкл/выкл).

### 2.4. Резервное копирование и сброс (Data Management)
- **Полный экспорт базы данных:** Выгрузка единого JSON-файла (`gtg-backup-YYYY-MM-DD.json`), содержащего всю историю тренировок, программу и настройки.
- **Импорт базы данных:** Восстановление всей истории и программы из бэкапа.
- **Опасная зона (Danger Zone):** Кнопка полного сброса данных с модальным окном подтверждения двойного действия.

## 4. Критерии приемки (Acceptance Criteria)

- [ ] **Редактирование нормативов:** Изменение числа подходов или названия упражнения мгновенно отражается на главном экране для текущего дня.
- [ ] **Защита истории (Регрессионный тест):**
  - Пользователь удаляет упражнение из Дня А.
  - Переходит в Историю за вчерашний день — удаленное упражнение по-прежнему отображается со всеми выполненными подходами.
- [ ] **Валидация JSON:** При попытке сохранить поврежденный или невалидный JSON программа выдает понятную ошибку и не ломает приложение.
- [ ] **Экспорт и Импорт:** Сгенерированный JSON бэкапа успешно импортируется в пустом браузере (Incognito) с полным восстановлением данных.
- [ ] **Настройка таймера:** Изменение времени отдыха (например, на 45 минут) меняет порог срабатывания зеленого статуса готовности на главном экране.

---

## 5. Проверка работоспособности (No-Regression Check)
1. Экспортировать JSON бэкапа.
2. Очистить `localStorage` через DevTools, нажать кнопку «Импорт» и выбрать скачанный файл — все данные должны восстановиться.
3. Отредактировать программу, добавить новое упражнение — проверить его появление на главном экране.
4. Проверить `npm run build` — сборка без предупреждений.
